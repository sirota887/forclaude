# Задания для облачной сессии

Репозиторий ПУБЛИЧНЫЙ (приватные недоступны по региональным ограничениям GitHub). Всё платное хранится только зашифрованным.

## Правила безопасности (нарушать нельзя)

1. Перед любой работой: `git config core.hooksPath .githooks` и `chmod +x tools/*.sh .githooks/pre-commit`.
2. Ключ — в переменной окружения `AGENTBIT_KEY` (владелец передаст его сообщением в чат, если в окружении его нет: тогда `export AGENTBIT_KEY='...'` в каждой оболочке; ключ НИКОГДА не писать в файлы репозитория, коммиты, логи и ответы).
3. Расшифровывать и работать только в папке ВНЕ репозитория: `tools/unpack.sh encrypted/guide-src.tar.gz.enc ~/work`.
4. Результаты шифровать `tools/pack.sh <папка> <имя>` и коммитить только `encrypted/*.enc`. В `public/` — только то, что и так будет публичным (сценарии роликов, тексты для соцсетей), без текста платных материалов.
5. Коммитить и пушить после каждого завершённого блока, чтобы прогресс не потерялся. Никогда не обходить хук (`--no-verify` запрещён) и не делать `git add -f`.
6. Субагентов и воркфлоу запускать на модели Sonnet: бюджет облака ограничен.

## Исходные материалы

`encrypted/guide-src.tar.gz.enc` → папка `guide-src/`:
- `SPEC.md` — правила, стиль, маскот Бит (обязательны: без названий компаний в заголовках и оформлении, без инструкций по обходу блокировок и VPN, без обещаний дохода, без выдуманных фактов, объяснять каждый термин и сленг простыми словами, без эмодзи);
- `OUTLINE.md` — план большого гайда; `chapters-v2/` — готовые главы (22 главы + шаблоны, словарь, источники);
- `templates/` — шаблоны; `research/` — выжимки популярных гайдов с источниками;
- `SITE-SPEC.md` — уровни продукта.

## Задание 1. Практика → `encrypted/praktika.tar.gz.enc`

Папка `praktika/`:
1. `navyki/<профессия>/` для 15 профессий (дизайнер интерьеров, фотограф, бухгалтер на аутсорсе, маркетолог-SMM, репетитор, психолог-консультант, юрист-консультант (без юр. советов в шаблонах), риелтор, владелец кофейни, мастер маникюра, копирайтер, переводчик, менеджер интернет-магазина, HR-рекрутер, организатор мероприятий): в каждой — файл инструкций проекта (`AGENTS.md`), 3 навыка (`<навык>/SKILL.md` с описанием, когда применять, шагами, примером), 3 готовых брифа, короткий `README.md` «как начать за 15 минут».
2. `scenarii/` — 30 сценариев «под ключ» (по файлу на сценарий): задача, бриф для копирования, как выглядит хороший результат, как проверить, частые ошибки. Сценарии не повторяют главы 15–17 гайда, а дополняют.
3. `tetrad.md` — рабочая тетрадь на 30 дней: задание на день (15–30 минут), чек-лист, место для заметок.
Всё простым языком по правилам SPEC.md, ссылки на главы гайда — по номерам из OUTLINE.md.

## Задание 2. Система → `encrypted/sistema.tar.gz.enc`

Папка `sistema/`:
1. `komandy/` — 4 готовые «команды агентов» (контент на месяц, исследование рынка с источниками, сайт-визитка от брифа до публикации, бот-ответчик на частые вопросы): роли, их запросы, порядок передачи работы, проверка результата, сколько это стоит в токенах (принцип, без точных цен), как запустить в типичных инструментах (описательно).
2. `zaprosy-100.md` — 100 заготовок запросов по категориям, каждая с пояснением «когда» и «что подставить».
3. `razbory/` — 10 подробных разборов (текстом, со схемами в Markdown): реальная задача → как ставили → где агент ошибся → как исправили.

## Задание 3. Сценарии роликов → `public/video/` (публично)

60 сценариев коротких роликов (до 45 секунд) и 12 длинных (6–10 минут) по главам гайда для YouTube-канала с маскотом Битом: хук в первые 2 секунды, текст закадра, раскадровка (что на экране), субтитры, призыв «гайд по ссылке в описании» без обещаний дохода. Без названий компаний в заголовках. Плюс `public/video/schedule.csv` — график публикаций на 12 месяцев (2 коротких в неделю, 1 длинный в месяц).

## Порядок и отчёт

Задание 1 → коммит → Задание 2 → коммит → Задание 3 → коммит. В конце допиши в этот файл раздел «Отчёт» (только числа и имена архивов, без содержимого).
